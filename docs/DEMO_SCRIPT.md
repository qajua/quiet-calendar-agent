# 1–2 分钟演示分镜与台词

目标：同一镜头中让观众看清“面试官正常使用手机”和“Agent 在后台完成真实日历任务”，并看到电脑端的独立回读结果。建议拍一镜到底，手机和电脑控制台同时入画；无需展示 API Key。

## 录制前准备（不计入视频）

1. USB 连接华为手机，运行 `adb devices -l`；确认日历权限、通知使用权和可写日历 ID。把测试来源限制为 `com.android.shell`，并先清空旧通知：`python3 tools/notification_bridge.py configure com.android.shell`、`python3 tools/notification_bridge.py clear`。
2. 选一个确认空闲的日历和时段。以下日期仅是 **2026-09-23 当周**的示例，正式录制可换成面试当天的未来日期，并同步修改通知文案。创建两条 Agent 所有的测试事件：

   ```bash
   python3 tools/quiet_cli.py create --task-id film-seed-001 --calendar-id 1 \
     --title "客户复盘" --start "2026-09-24T14:00:00+10:00" --minutes 30
   python3 tools/quiet_cli.py create --task-id film-busy-001 --calendar-id 1 \
     --title "演示占位" --start "2026-09-25T16:00:00+10:00" --minutes 30
   ```

3. 在**启动控制台的同一个终端**设置 `OPENAI_API_KEY` 和 `OPENAI_MODEL`，启动 `python3 tools/control_center.py --calendar-id 1 --open`。先用一次完整彩排确认模型能解析通知、控制台能执行、16:00 冲突后选择 16:30、会议和会后事项均回读成功；彩排后执行整体撤销并使用新的测试任务 ID。当前自动化测试不能替代这一步。
4. 让持机者打开聊天输入框并开始打字；录制前确认测试通知不会以横幅遮挡输入。如果会遮挡，只调整测试通知频道为静默并重新彩排，保持录制过程如实呈现。

## 约 100 秒的连续镜头

| 时间 | 画面与操作 | 建议台词 |
| --- | --- | --- |
| 0–12 秒 | 镜头同时拍到手机聊天输入框和电脑控制台；持机者持续输入。 | “手机现在由使用者正常操作，Agent 不会接管这块屏幕。” |
| 12–25 秒 | 电脑另一终端发送测试通知；控制台出现 `MEDIUM · needs_confirmation`。 | “任务从这台手机收到的通知进入。它先判断风险，修改日历必须得到我的确认。” |
| 25–35 秒 | 控制台展示通知正文；操作者点击“确认并执行”，持机者继续打字。 | “我在电脑上批准这条任务；手机端不弹审批框。” |
| 35–70 秒 | 控制台显示 `executing`；手机保持聊天界面，持机者继续输入。 | “Agent 正在手机后台处理；执行期间用户仍在操作这块屏幕。” |
| 70–90 秒 | 控制台显示 `complete`，展开最终输出中的冲突决策、改期事件、20 分钟提醒和会后任务回读；镜头扫到仍可输入的手机。 | “16 点有冲突，因此选了 16 点半。会议、提醒和会后事项均已重新读取；Agent 没有进入前台。” |
| 90–105 秒 | 展示“整体撤销”按钮；如时间允许点击并展示 `undone`，否则保留最终完成状态作为片尾。 | “结果可核验，也能按相反顺序整体撤销。” |

发送通知的命令（单独终端，使用与种子事件一致的日期和标题）：

```bash
python3 tools/notification_bridge.py test --title "日程助理" \
  --text "把2026年9月24日14点的客户复盘改到2026年9月25日16点；若冲突找之后最近空档，提前20分钟提醒，并在会后创建30分钟整理会议纪要"
```

## 录制判定与收尾

- 只在控制台出现 `complete`、会议/提醒/会后事项回读值正确、手机在整个执行窗口持续可操作时，使用“办好了”的台词。如果模型要求澄清、超时或某一步失败，停止该次录制，先定位原因再重新彩排。
- 若本次执行超过两分钟，保留完整原始录像用于排查，优化后重录；不要剪掉等待过程再声称是 1–2 分钟连续演示。
- 视频同时保留手机屏幕、手指输入和控制台关键结果；采样日志只证明检测时刻的前台状态，不能代替连续实拍。
- 若录制了撤销，先确认 `undone`；然后执行 `python3 tools/quiet_cli.py cleanup --task-id film-seed-001` 和 `python3 tools/quiet_cli.py cleanup --task-id film-busy-001`。若未撤销，先从控制台整体撤销再清理。不要清理不属于本次演示的事件。
